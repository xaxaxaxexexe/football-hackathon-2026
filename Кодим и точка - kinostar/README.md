# Арена 3D — билет с видом на поле

Визуальная адаптация проекта «Киностар» под кейс «Билет с видом на поле»: афиша стала расписанием матчей (`schedule-data.js`, карточки матчей в `assets/match-*.svg`), залы — секторами, кинобар — фуд-кортом, а в 3D вместо экрана поле 105 × 68 м с трибунами, прожекторами и табло (`hall-scene.js`). Живая афиша кинотеатра больше не подгружается. Стадион, клубы и матчи вымышленные, оплата демонстрационная. Ниже — исходное описание проекта.

Запуск через Docker: `docker compose up --build -d`.
Откройте http://localhost:4173. База SQLite находится в постоянном Docker-томе
`kinostar_data`: аккаунты, сессии входа и заказы сохраняются после перезапуска.
Остановить сайт: `docker compose down` (данные остаются в томе).

Локальный запуск без Docker: Node.js 24+, затем `npm run dev`.
Открыть http://127.0.0.1:4173. Устанавливать зависимости не требуется.
Для оформления заказа нужен именно этот сервер, а не открытие HTML файлом.
Проверка: `npm test` (19 проверок движения, экрана, звука, расписания,
корзины, регистрации, оплаты и выдачи локальных файлов).

Проект подготовлен для GitHub: есть `.gitignore`, `.dockerignore`,
`Dockerfile` и `compose.yaml`. Файл `.env`, база и изображения предпросмотра
не попадают в Git или образ Docker. Репозиторий Git уже инициализирован.
Чтобы загрузить код, создайте пустой репозиторий GitHub и выполните
`git add .`, `git commit -m "Initial Kinostar site"`,
`git remote add origin <адрес-репозитория>`, `git push -u origin main`.
Перед отправкой убедитесь, что текущая ветка называется main:
`git branch -M main`.

Кнопка «Войти / Регистрация» создаёт аккаунт по почте и паролю от 10 символов.
Пароль хранится только в виде хеша; вход запоминается в защищённой cookie.

## Сценарий

1. Выбрать сеанс в афише. Открывается фойе у регистрации и кинобара.
2. Открыть кинобар клавишей E или кнопкой, собрать заказ и увидеть сумму.
3. Пройти по Г-образному коридору до нужного зала. На плане семь дверей:
   4 и 1 слева, 2/3/5 справа, 6/7 после поворота. Гардероб у поворота.
4. Войти в свой зал, пройти между рядами, сесть на кресло и осмотреться.
5. «Начать → к оплате» открывает состав заказа с выбранными сеансом и местом.
6. В локальном режиме пройти демонстрационную оплату без списания денег.

WASD / стрелки — ходьба; Shift — быстрее; мышь с зажатой кнопкой — осмотр.
«Управлять мышью» включает захват курсора, если браузер поддерживает.
Esc освобождает курсор. E — действие / сесть / встать. Пробел — встать.
На телефоне удерживать стрелки и вести пальцем по сцене.
«Показать направление» поворачивает камеру к залу или к повороту коридора.
«К выбранному креслу» позволяет быстро вернуться к выбранной точке.

Кресла моделировались по фото: чёрная обивка, отдельные широкие
подголовники, боковые валики, подлокотники и подстаканники. Проходы
по бокам, красные ступени, вертикальные белые светильники.
Коридор построен по рисунку. Размеры ориентировочные. Во всех залах
пока одна демонстрационная геометрия 8×14, не реальная схема мест
каждого из семи залов. Для точной копии нужны обмеры и схемы залов.
Занятость мест — демонстрационная, реального бронирования нет.

## Экран и управление для презентации

Экран увеличен с 12,4 × 5,17 до 22,32 × 9,306 м: в 1,8 раза по каждой
стороне, в 3,24 раза по площади. Ширина зала теперь 24 м, высота 11,6 м.
Передняя стена отодвинута до z = −4,6 м, экран — до z = −4,25 м;
до первого ряда 9,25 м. Все 112 кресел, номера рядов и высоты ступеней
сохранены. Общие размеры находятся в `hall-model.js`, геометрия — в
`hall-scene.js`. Три мягких источника света освещают стены и первые ряды.
Проектор виден с заднего прохода: повернитесь назад и немного вверх.

Текстура экрана имеет ширину 2048 пикселей, сохраняет пропорции и показывает
название выбранного фильма, дату, время и зал. Это заставка сеанса,
а не воспроизведение фильма. Поле зрения адаптируется к портретному экрану.

При первом входе появляется подсказка; повторно открыть её можно кнопкой
«Как гулять». Нужная дверь и выбранное кресло выделены оранжевым, на плане
показаны маршрут и направление взгляда. На небольших экранах план можно
развернуть кнопкой «План». Анимация появления учитывает reduced motion.

## Пространственный звук

Кнопка «Звук включён» / «Звук выключен» доступна в верхней панели и фойе,
и зала. При первом посещении тихий звук включается после нажатия
«Начать прогулку», клика или клавиши внутри 3D. До взаимодействия
AudioContext не создаётся. Выключение сохраняется в `localStorage`
(`kinostar.sound`), после перезагрузки его нужно включить кнопкой.
Закрытие прогулки, открытие кинобара поверх сцены и скрытие вкладки
плавно приглушают звук и приостанавливают контекст.

В `cinema-audio.js` добавлены семь позиционных источников:

- атмосфера фойе и отдельный шум кинобара;
- приглушённый звук у двери выбранного зала;
- вентиляция у поворота коридора;
- тихий фон в зале;
- механический звук проектора сзади;
- вентиляция сбоку зала.

Используются Three.js AudioListener на камере, PositionalAudio с HRTF
и затуханием по расстоянию. При переходе между сценами их звуки плавно
переключаются. Общая громкость ограничена, включён мягкий компрессор.
Это оригинальные синтезированные эффекты Web Audio, распространяемые
с кодом проекта по MIT: записей речи и сторонних аудиофайлов нет.
Шесть коротких моно-буферов создаются локально в памяти (около 3,5 МБ),
вентиляция использует один общий буфер. Звук не загружается и не отправляется
в сеть. Без Web Audio прогулка работает в тишине, кнопка недоступна.

Для проверки презентации: выбрать сеанс → начать прогулку → переключить
звук → пройти до выделенной двери → войти → пройти по боковому проходу
и между рядами → посмотреть на кресло и нажать E → оценить экран.
Сравнить звук проектора у задней стены и возле первого ряда; в наушниках
проверить направление при повороте головы. Проверить также телефон в
портретной и альбомной ориентации. Громкость устройства следует подобрать
на месте: автоматические проверки аудиосигнала не заменяют прослушивание
на колонках презентации.

## Меню

Попкорн: S 200 ₽, M 350 ₽, L 550 ₽ — цены заказчика.
Lipton зелёный 0,5 л — 180 ₽; Добрый Кола 0,5 л — 180 ₽;
вода без газа 0,5 л — 120 ₽; чипсы сыр 70 г — 200 ₽.
Цены напитков и чипсов демонстрационные, меню кинотеатра не предоставлено.

Ассортимент сверялся с публичными карточками товаров, эти источники
не подтверждают цены и наличие в кинотеатре:
- Lipton: https://av.ru/i/332813
- Добрый Кола: https://monetka.ru/product/napitok-dobryjj-kola-silnogazirovannyjj-05l-rossiya-810004572/

Цены находятся в catalog.js в целых копейках. Корзина хранится локально
в браузере; сумма заказа повторно считается сервером. Переданные
браузером цены и итоговая сумма не используются. Билет в демонстрационном
заказе рассчитан по нижней цене сеанса и явно отмечен как ориентир:
реальные тарифы отдельных кресел не подключены.

## ЮKassa

По умолчанию PAYMENT_MODE=demo: запросы в платёжный сервис не отправляются.
Успешная демонстрация имеет статус demo_completed, а не succeeded.

Для подключения тестового магазина скопировать .env.example в .env:
- PAYMENT_MODE=yookassa_test
- YOOKASSA_SHOP_ID — идентификатор тестового магазина
- YOOKASSA_SECRET_KEY — тестовый секрет test_...
- PUBLIC_BASE_URL — адрес возврата на этот сайт

Секреты вводить только в серверное окружение. Не отправлять в чат,
не помещать в HTML/JS. Сервер отдаёт только явно разрешённые файлы;
.env, база заказов и серверный код недоступны посетителю.

Создание платежа выполняется сервером через API v3 с Basic Auth,
стабильным Idempotence-Key, capture=true и возвратом по order ID.
Возврат из ЮKassa не означает успех: сервер получает статус платежа,
сверяет test=true, paid, сумму, валюту, order_id и payment ID.
Уведомления POST /api/yookassa/webhook также перепроверяются через API.
Поддельное уведомление не может подтвердить оплату.
Заказы сохраняются в .data/orders.sqlite и переживают перезапуск.

Настоящий тестовый магазин ещё не проверен: его доступы не предоставлены.
Автоматические тесты используют ответы имитатора провайдера.
Ключи боевого магазина и режим live сервер намеренно не принимает.
До реального запуска необходимо подключить:
- схемы, тарифы и атомарное резервирование мест в кассовой системе;
- подтверждённое меню и наличие товаров;
- реквизиты магазина, систему налогообложения и передачу фискальных чеков;
- выдачу билетов, снятие резервов, обработку отмен и возвратов.

Текущий «предварительный чек» — состав заказа, не фискальный документ.

Документация:
https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start
https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing

## Афиша и оформление

Используется публичный источник kinostar-groznymall.com (Киноплан,
кинотеатр 8436, город 16). Загружаются все опубликованные даты и сеансы.
При недоступности источника показывается сохранённая копия с датой.
Импорт от 7 ноября 2026: одна дата, 19 фильмов, 32 сеанса.
Сохранённое расписание и постеры: `node tools/sync-schedule.cjs`.
При оформлении неизвестного сохранённой копии сеанса сервер обновляет
расписание из того же источника.

Логотип, постеры, фиолетовый #4a148c и оранжевый #ff3d00 перенесены
с сайта кинотеатра по запросу заказчика. Официальная покупка билета
доступна отдельной ссылкой со схемы мест.
